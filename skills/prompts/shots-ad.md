## 本片体裁：广告 / 品牌短片

上游素材是**广告片脚本稿**（创意核心 / 主体设定 / 空间与光线连续性 / **转场表** / 分场（段落）剧本），不是按场次铺开的剧集剧本。

下文只规定五件事：**怎么切镜、切多少个、每镜多长、景别怎么走、场景名从哪来**——再加本体裁独有的转场配对、旁白与字卡、产品当主角。镜头内部的写法（continuity 快照、对白带说话人名、`action` 末句完成态、JSON 字段）一律照基座。

### 一、素材形态：段落就是「场次」

- 第五部分的「段落」= 基座说的「场次」；段落头 `段落 1：花海公路·外` 里的「地点·内外」照抄进 `shots[].scene`，**逐字复制、不带上「段落 1：」这个前缀**。
- 🔴 **`shots[].scene` 只能取脚本里逐字出现过的空间名**——要么来自第三部分的空间档案名，要么来自第五部分段落头的「地点·内外」。**不许自造、不许拼接、不许给已有名字加 `·内` / `·外` / 季节词后缀**：编出来的名字在第三部分找不到对应档案，下游只会为它建一张**空档案**，出的空镜图与本片毫无关系（实测案例：把段落头「四季公路」自己拆成「四季公路·内」，主空间那张有内容、车内那张是空的）。
- 🔴 **只有空间名完全相同，才合并成一个场景**：脚本第三部分把若干段落写成**同一条**空间档案、且第五部分段落头用**同一个**名字时，`scenes[]` 只有一条，全片共用它（「同一条街从清早到深夜」那种情形）。**段落头各有各的地点名时（花海公路 / 湖岸公路 / 山林弯道 / 雪原公路），就是四条不同场景，逐条建档案**——它们是四个不同的可拍空间，不是「同一个空间的四个时段」；「这几个段落是一条连贯的线」由每条镜头的 `continuity` 与转场配对表达，**不靠合并场景名**：并成一条的后果是下游只拿到一张空镜参考图，地点差异全丢。
- 🔴 **段落内部的镜头若处在段落头之外的另一个空间**（车厢内、机舱、船舱、电梯轿厢、隧道内、帐篷内这类与主空间不同的封闭 / 半封闭空间），**该用哪个名字只看一件事：这条镜头能不能用段落头那张空镜参考图。**
  1. **能用**（镜头其实还在段落头那个空间里，只是换了机位 / 角落 / 景别）→ 沿用段落头名，把差异写进 `action` 的机位描述；
  2. **不能用**（车外那张图给不了车内、楼道那张图给不了电梯轿厢）→ 它必须有自己的名字：脚本第三部分**为它建了空间档案**（例：`座舱·内`）就逐字照抄那条档案名；脚本第三部分**没有为它建**（上游漏了）→ 按「地点·内外」起一个**只说空间的名字**（不许抽象、不许带情节或人物），并在本批 `scenes[]` 里为它建一条 **profile 非空** 的档案（**这是上一条「不许自造」的唯一例外**）。
  ⚠️ 不要让两个不同空间的镜头共用同一个场景名——上下两个空间的画面完全不同，共用一名只能出一张空镜参考图，另一个空间注定拿着一张不相干的环境图去生成。

### 二、一镜装多少：最多 2 个画面单元

「整段照搬」有上限——**数一数这段话里有几个画面单元**：

- **一个画面单元** = 一次「换空间」或「换机位」。判据很直接：句子之间的**分号**、以及「**镜头切回 / 切至 / 切换 / 拉远 / 推近 / 随即**」这类词，都在提示这是一个新单元；从车外切到车内（或任何两个不同空间之间）**必然**是跨单元。
- **1-2 个单元 → 一个镜头装得下**：整段照搬，`dur` 至少 4 秒（2 个单元时给到 6 秒以上）。
- **3 个及以上单元 → 必须拆镜**：这不是「上游分得太细」，而是它把本该两条镜头的内容压进了一段。**按单元边界拆成 2 条**（第一条覆盖前 1-2 个单元、第二条覆盖剩下的），**每条 `dur` 不低于 4 秒**。此时镜头数会超过「段落数 × 1」，这是允许的——上限仍是段落数 × 1.5（见「四、镜数」）。
- 🔴 **该段落声明的秒数 > 15 秒 → 这一镜也必须拆**：「一镜最多 2 个画面单元」管的是**画面**，这一条管的是**时长**。单镜生成上限 15 秒是硬顶：把声明 20 秒的段落塞进一个 15 秒的镜头，模型只能自由发挥把画面拖满（拖沓、空转、尾帧失控），而且全片所有镜头加起来还装不满脚本声明的总时长（实测 V9X-4：脚本 105 秒，6 个镜头 × 15 秒只装得下 90 秒）。判据 = **这条镜头所在段落声明了几秒，就至少要有 ⌈秒数 ÷ 15⌉ 个镜头**（20 秒 → 2 个，25 秒 → 2 个，31 秒 → 3 个），**按段落内部的画面单元边界切**，每条仍 ≥ 4 秒。
  ⚠️ 这条**程序也会自己算一遍并自动补镜**（`promptlib.fitShotCount`，生成分镜时自动跑、只做加法、绝不做合并）—— 所以你少拆了不会漏；但程序是**按标点粗切**的兜底，画面远不如你按镜头语言干净地切开。
- 🔴 **一镜只能属于一个空间**：`action` 里同时出现车外与车内（或两个空间名）→ 必然跨单元 → 拆镜。拆出来的车内那一条，`scene` 按「一、素材形态」里「段落内部的镜头处在另一个空间」那条规则命名。
  ⚠️ 不拆的后果很硬：车内画面那一条只能挂着「花海公路·外」这种**车外空镜**当环境参考，而那份档案的 prompt 写着「室外」、negative 里写着「人物 / 演员 / 人像」，生成出来的车内环境与参考图毫无关系。
- 🔴 **`camera` 必须覆盖 `action` 里的每一次机位变化**：`action` 写了「镜头切回车内」，`camera` 就要出现对应的「切回车内」；`action` 从车外开始、在车内结束，`camera` 也必须从车外写到车内——**顺序一致、不漏段**。实测反例：某镜 `action` 是「驶入隧道 → 驶出隧道 / 落叶漩涡 → 车轮碾落叶 → 切回车内驾驶者」，`camera` 却只写了「车内中景推近至驾驶者面部特写」，前 2/3 完全没覆盖，下游的机位信息就丢了。

### 三、切镜：按段落切，不按动作单元切

- 🔴 **一条段落 = 1 个镜头（默认）**。上游改编稿（`adapt-ad.md` rev5）已经把每段写成「一整段连续画面」，换机位、换景别、推近都写在**同一段话**里。所以正常情况就是**一段一镜**——把那段话整句搬进这一镜的 `action`（景别与运镜摘进 `camera`），**不要按句号 / 分号把它拆成好几镜**。
- 只有两种情况才断开：① **进入下一个段落**；② 这一段里确实有**两个互不相干、各自能独立成图**的画面主体（上游会为此写成两段）。
- ⚠️ 这与剧集的「一个动作单元一个镜头」是两种不同的剪法，不要混用：广告片按**段落**，不是按动作。
- 段落头下面那些「时间地点行」「转场说明行」不是画面，不要为它们开镜。

### 四、镜数：按段落数算，不按字数算

- 🔴 **一条段落 = 1 个镜头（默认）**，全片上限 = **段落数 × 1.5，向上取整**：5 段 ≤ 8 镜，8 段 ≤ 12 镜，12 段 ≤ 18 镜。
  ⚠️ 这个上限**程序会真的判**（`promptlib.shotCheck`，参数由 `electron/styles/axes/genre/ad.json` 的 `limits` 声明）：生成完超过上限会自动弹「一键合并」，所以别指望多写几条能蒙过去。
- 🔴 **算术自检（输出前必须过）**：`镜头数 ≤ 脚本总秒数 ÷ 4`（4 秒是单镜硬下限，也是基座契约里的 `dur` 下限）。例：30 秒的片子最多 7 镜；超了就说明你在把一句话切成两镜，回去合并。
- 🔴 **不要为了「完整」把广告片拉成剧集的镜头密度**——镜头多一条，视频就多一次独立生成，漂移风险随之放大。**转场配对（见「十、转场配对」）是该拆的地方**；除此之外一律**合并优先**：同一段落内机位连续就并成一镜，旁白 / 字卡并进画面镜。

### 五、时长：贴住段落的声明秒数

- 🔴 **每一镜的 `dur` 要贴近它所在段落的声明秒数**——段落声明 8 秒，这一镜就大约 8 秒，不要给 6 秒；一段拆成两镜时，两镜之和 ≈ 该段秒数。
- 🔴 **总时长自检**：全部镜头 `dur` 之和必须落在「脚本各段秒数之和」的 **±20%** 以内（例：脚本各段合计 30 秒 → 分镜总时长 24-36 秒）。这是最灵敏的报警器：镜头数一多，总时长必然爆。
- 🔴 **逐段对齐**：总和对了不等于分配对了。实测反例：段落声明 8 / 8 / 5 / 5 / 2 秒，分镜给成 6 / 6 / 4 / 6 / 6 —— 总时长 28 秒一分不差，但前两段各欠 2 秒、最后一段多出 4 秒（声明 2 秒给了 6 秒）。**总时长那一条过不了「逐段」这一关**。
  🔴 这条**程序会真的判**（`promptlib.shotCapacity` 的 `capacity-seg`）—— 某段落声明 20 秒却只分到 1 个镜头（容量 15 秒）即判不合格；生成分镜时还会**自动按段落秒数补镜**（`fitShotCount`，只做加法、绝不做合并）。
- 🔴 **段落声明秒数的自洽区间：每段 ≤ 15 秒**。一笔账：单镜上限 15 秒 + 一段一镜 + 镜头数上限 = 段落数 × 1.5。段落声明 20 秒时，它自己要吃掉 2 个镜头名额；`Σ⌈段落秒数 ÷ 15⌉` 一旦超过 `段落数 × 1.5`，**脚本对本体裁就不自洽了**（程序会判 `capacity-script`，让你回改编稿重拆）。写成 ≤ 15 秒则「一段一镜」天然满足，`Σ⌈段秒 ÷ 15⌉` 恒等于段落数，永远不自相矛盾。
- 每镜仍必须落在 **4-15 整数秒**（基座硬约束）；段落声明秒数低于 4 秒时，说明上游拆错了，回改编稿并进上一段，不要在这里硬写 3 秒。

### 六、景别：细节特写优先

- 🔴 **大件产品（汽车、家电、数码）的质感全在特写里**：车灯纹理、轮毂反光、缝线、按键、品牌徽标这类局部，该给特写就给特写，不要整片都是远景全景。
- 这里没有「远→中→近递进」的要求，也没有「特写不宜连续两个」的限制——广告片的逻辑是「哪个局部能证明卖点，就给哪个局部」，连续两个特写是正常的。
- 但**相邻镜头的收尾景别仍要避免无意义的重复**：连续两条都是同一机位同一景别的全景，等于浪费一次生成。

### 七、场景名从哪来

- 名字**只能逐字照抄脚本**（第三部分空间档案名 / 第五部分段落头），判据见「一、素材形态」——那里写全了「不许自造 / 介质空间例外 / 同空间才合并」三条。
- 名字里只留「地点·内外」：**不许用括号加限定词**（`花海公路·外（春）` ×、`座舱·内（全片共用）` ×），季节与用途说明一律写进档案正文。
- 时段（日 / 黄昏 / 夜）不进名字；同一条路的不同季节，用**该季节最有辨识度的景物**分别命名（花海公路·外 / 梧桐荫公路·外 / 层林公路·外 / 雪原公路·外）。

### 八、声音：旁白行与字卡行

脚本里的 `旁白：「…」`、`字卡：「…」` 与 `说话人：「…」` 一样，直接写进该镜的 `dialogue` 字段，格式不变（`冒号前是发声者`，全角冒号）。

🔴 **旁白行 / 字卡行不许单独成镜（本体裁最容易被违反的一条）**

- 脚本里 `旁白：「…」` 与 `字卡：「…」` 是**同一句文案的两种落地方式**（一个念出来、一个打在画面上）。它们**属于**那条画面镜，**不是**一镜。
- 写法：把旁白写进该段落**主力镜**的 `dialogue`（`旁白：原句`），同一句字幕写进**同一镜**的 `action`（例：`画面下方浮现白色无衬线字幕：原句`）。**一句文案 = 同一镜里的一次交代**，不许前一镜写旁白、后一镜再把同一句写成字卡。
- 输出前逐镜检查 `action`，过一遍这一问：**「这一镜里除了字幕，还有什么可拍的画面？」** 答不上来的镜头，一律并进相邻镜头，不许留下。整镜 `action` 只有一条字幕是最严重的错误之一——它没有任何画面信息，视频模型只能自由发挥，是漂移与接缝断裂的最大来源。
- 若某段落只有旁白 / 字卡、一条画面描述句都没有（罕见），把它的文案并进**相邻段落**已有镜头的 `dialogue`，不要为它单独建镜。
- `字卡` 的内容通常是品牌名 / 型号 / slogan，属于**画面文字**：写进 `dialogue` 的同时，也要在对应 `scenes[].profile` 里按「带字载具」写出确切文字（载体 + 「文字」 + 字数 + 字体）。
- 🔴 **旁白与字卡不是角色**：不要为它们在 `characters[]` 里建条目，也不要写进 `shots[].chars`。`chars` 只写真正出现在画面里的主体。为「旁白」建一张角色卡会去生成一张根本不需要的参考图。

### 九、画面内的品牌文字

品牌名、slogan、型号文字都属于「画面里会出现的确切文字」，与基座的通用要求一致：**载体 + 「文字」+ 字数 + 字体**四件事必须写全，不许只写「有品牌标识」。分镜里出现的每一处文字，都要能在对应 `characters[].profile` 或 `scenes[].profile` 里逐字找到出处。

### 十、转场配对（本体裁最重要的一条）

转场表里的每一条 = **一对镜头**（前一段结尾的那一条 + 后一段开头的那一条）。

上游（`adapt-ad.md`）已经把「前一段结尾」写在**该段的最后一句**、「后一段开头」写在**下一段的第一句**；而**一段默认一镜**，所以这一对通常就是**相邻两个段落的那两个镜头**。配对时逐条核对：**上一镜 `action` 的结尾**与**下一镜 `action` 的开头**是否共享那个共同元素、两条 `camera` 是否写了相同的景别与机位。这一对必须：

1. **相邻**：两条镜头紧挨着，中间不许插入任何其它镜头——插一条就接不上了；
2. **同景别同机位**：两条的 `camera` 必须写出**相同的景别与机位**（例：两条都写 `挡风玻璃特写，低机位`）。下游靠这一点把它们配成一对，让前一条的末帧接上后一条的首帧；
3. **共享共同元素**：前一条的 `action` 必须**收在**那个共同元素上（例：雨刷自左向右扫过挡风玻璃，把花瓣推离，留下一道水痕）；后一条的 `action` 必须**从一个等价动作开始**，并在句首显式写出承接关系：

```
承接上一镜的雨刷动作，同一个景别与机位，雨刷继续自左向右扫过，这次推开的是暴雨的水幕。
```

4. **快照成套**：后一条的 `continuity` 里，时段 / 天气 / 环境要写成「承接上一镜的同一个……」或明确写成换季，不要含含糊糊；共同元素涉及的维度按它当下的状态写全。
5. **这一对镜头都必须有可拍的画面主体**：车、人、物件、天气都行，但不许是纯字幕镜或纯空镜——它们在成片里是**接缝**，接缝处最怕模型自由发挥。转场镜里只写一条字幕，等于把接缝交给模型随机画。

🔴 **转场镜必须写 `change`**：若这次切换本身就是画面里看得见的一个动作（雨刷刷过、车头穿过隧道口、一片花瓣落下变成一片梧桐叶、光线由冷白变暖金），**这一镜的 `change` 不得留空**，按「主体·维度：旧值 → 新值（触发动作）」写。

```
挡风玻璃·物体：粉色花瓣 → 枯黄梧桐叶（落地瞬间形态置换）
光线·色温：隧道内冷白 → 出隧道后暖金（驶出隧道口）
```

- **为什么是硬的**：视频规范（`h3.md` / `h3ref.md`）里有一个专门填 `change` 字段的占位符，原文是「这一镜是状态变化发生的地方，变化必须在画面上看得见，结尾必须落在新值上」。**`change` 留空时，程序会把这一整段引导连同提示句一起跳过**（空值占位符所在的那一段会被整块删掉）——模型就不知道该把什么变成什么，转场那一镜的尾帧落不到新值上，前后两条镜头接不上。而本体裁的骨架恰恰是转场（物体匹配 / 光线过渡），几乎每一镜都落在「状态变化发生的地方」。
- **只在 `action` 里真的写了那个动作时才写**——程序会检查「标了状态变化，但本镜画面动作里没有这个动作」。**非转场的镜头照旧留空**，不要硬造。

### 十一、产品当主角

- 产品要在 `characters[]` 里建一条档案：`name` 用脚本里的固定称谓，`role` 写 `产品`。档案字段改用**产品维度**：`名称 / 品类 / 外观与配色 / 材质与反光 / 品牌标志与文字 / 重点局部 / 依据`。与产品无关的字段（性别 / 年龄段 / 胡须 / 面部基线）**整行省略**，不要写「未知」。
- 🔴 **细节特写优先**：车灯纹理、轮毂反光、缝线、按键、品牌徽标这类局部，每条都要给到特写；不要全片都是远景全景——大件产品的质感全在特写里。
- **一个卖点一条镜头**：素材里写到的卖点，每一条都要有对应的**可拍**镜头（「加速快」→ 起步时背景拉成横向拖影；「隔音好」→ 车窗外雨幕模糊、车内安静特写），不要只有旁白在讲。卖点必须能从画面里读出来，一个卖点对应一个可拍摄的物理事实。
- 产品与人物同框时，`shots[].chars` 两个都写。

### 十二、`setting` 的广告侧要求

- `光线基调` 写**全片**统一调子（例：`全片冷调、硬光、高对比`）；每个场景各自的光源方位写在场景档案的「主光」里。
- `轴线铁律` 写对话与走位的轴线规则；广告片常常没有人物对话，此时写「无人物轴线约束，以每镜机位连续性为准」也要给一句，**不得留空**。
- `声音基底` 写全片持续底噪与配乐基底（对白 / 旁白出现时一起让路、但不停止）。
- `禁止项` 至少一条，本体裁建议至少写明「禁止产品外观或配色变化」「禁止品牌标识文字变形」。
